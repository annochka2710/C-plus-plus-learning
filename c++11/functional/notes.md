# std::function, std::bind и делегаты

Модуль относится к **C++11 (2011)**. Все примеры в
[examples.cpp](examples.cpp) собираются именно в этом режиме.
Перед началом полезно знать функции, ссылки, классы, `const` и основы лямбд.
После заметок переходи к [самостоятельной практике](practice.md).

## Что к какому стандарту относится

| Возможность | Стандарт | Зачем нужна |
|---|---|---|
| Указатели на функции и методы, функторы с `operator()` | Уже C++98 | Основа передачи поведения |
| Лямбды, `std::function`, `std::bind`, `std::ref`, `std::cref`, `std::reference_wrapper`, `std::placeholders` | C++11 | Хранение и адаптация вызываемых объектов |
| Захват с инициализатором, например `[p = std::move(p)]` | C++14 | В том числе перенос владения в лямбду |
| `std::invoke` | C++17 | Единый способ вызова функции, функтора или указателя на член |
| `std::bind_front` | C++20 | Привязка первых аргументов без `_1` |
| `std::move_only_function`, `std::bind_back` | C++23 | Хранение перемещаемых обработчиков и привязка последних аргументов |
| Делегат как идея «сохранить обработчик и вызвать позже» | Без отдельной даты принятия | Это способ проектирования; стандартного `std::delegate` нет |

У `std::function` и `std::bind` были предшественники в Boost и TR1.
В основной стандарт C++ эти имена вошли в C++11. Старые `bind1st` и `bind2nd`
из C++98 — другие адаптеры.

## Вызываемые объекты и сигнатура

**Callback**, или обратный вызов, — обработчик, который передают другому коду,
чтобы тот вызвал его при нужном событии. Обработчиком может быть:

- обычная функция или указатель на неё;
- функтор — объект класса с `operator()`;
- лямбда, в том числе с захваченными данными;
- указатель на метод вместе с объектом, на котором его надо вызвать.

Сигнатура `int(int, int)` означает: принять два `int`, вернуть `int`.
Указатель на нестатический метод требует ещё и объект:

```cpp
struct Counter {
    int total;
    void add(int value) { total += value; }
};
Counter counter{0};
void (Counter::*method)(int) = &Counter::add;
(counter.*method)(5); // counter.total == 5
```

Указатель на метод не является обычным указателем на функцию и сам по себе
не хранит адрес конкретного экземпляра `Counter`.

## std::function: хранение обработчика с заданной сигнатурой

Заголовок для библиотечных средств этого модуля — `<functional>`.

```cpp
std::function<int(int)> operation = [](int x) { return x * 2; };
int result = operation(3); // 6
operation = [](int x) { return x + 10; }; // Другой тип лямбды, та же сигнатура.
```

У каждой лямбды свой тип. `std::function` скрывает конкретный тип обработчика
за общей сигнатурой; это называют **стиранием типа**. Поэтому в одном
`std::vector<std::function<int(int)>>` можно хранить разные лямбды и функторы.
Аргументы и результат должны быть совместимы с указанной сигнатурой.

По умолчанию обёртка пустая. `if (handler)` проверяет наличие обработчика.
Вызов пустого `std::function` бросает `std::bad_function_call`.
`handler = nullptr` очищает обёртку.

Обёртка хранит собственный целевой объект. При копировании `std::function`
копируется и этот объект, поэтому цель должна быть копируемой.
При этом копирование указателя или захвата по ссылке **не копирует внешний
объект**: несколько обработчиков продолжают обращаться к одному состоянию.

```cpp
int total = 0;
std::function<void(int)> add = [&total](int x) { total += x; };
auto another = add;
another(3); // total == 3: ссылка по-прежнему ведёт к исходному total.
```

`std::function` может выделять динамическую память и добавлять косвенный вызов.
Конкретные оптимизации зависят от реализации; не рассчитывай, что любая
маленькая лямбда обязательно обходится без выделения памяти.

## std::bind: новый вызываемый объект из существующего

`std::bind` связывает часть аргументов и задаёт, куда подставить оставшиеся.
Он возвращает объект неуказанного типа: обычно его удобно хранить через `auto`.
Помещать результат в `std::function` необязательно.

```cpp
int subtract(int left, int right) { return left - right; }
using std::placeholders::_1;
using std::placeholders::_2;
auto from_ten = std::bind(subtract, 10, _1);
auto reverse = std::bind(subtract, _2, _1);
// from_ten(3) == subtract(10, 3) == 7
// reverse(3, 10) == subtract(10, 3) == 7
```

`_1` означает первый аргумент **будущего вызова**, `_2` — второй.
Это не номера параметров исходной функции.

Обычные связанные аргументы сохраняются по значению: lvalue копируется,
rvalue может перемещаться. Чтобы сохранить обращение к исходному объекту,
используют `std::ref`, для константного доступа — `std::cref`.

```cpp
Counter counter{0};
auto copy = std::bind(&Counter::add, counter, _1);
auto reference = std::bind(&Counter::add, std::ref(counter), _1);
copy(5);      // Меняет внутреннюю копию; counter.total остаётся 0.
reference(5); // Меняет counter; counter.total становится 5.
```

Можно передать `&counter`: тогда сохраняется указатель. Ни указатель,
ни `std::ref` не продлевают жизнь `counter`.
`std::reference_wrapper<T>` — копируемая обёртка над ссылкой, а не владелец объекта.
Сама `std::function` тоже может хранить `std::ref(functor)`.

Тонкости для чтения чужого кода: лишние аргументы вызова `bind` могут
игнорироваться, но выражения этих аргументов всё равно вычисляются;
вложенный `bind` обычно вычисляется при вызове внешнего.
Для первых упражнений достаточно обычной привязки и перестановки аргументов.

## Лямбда вместо bind

```cpp
auto from_ten = [](int value) { return subtract(10, value); };
auto reference = [&counter](int value) { counter.add(value); };
```

В новом учебном коде предлагаю сначала писать лямбду: у неё явно видны
параметры, захваты и тело. `std::bind` полезно знать для чтения существующего
кода и понимания привязки аргументов; он не объявлен устаревшим в C++11–C++23.

`auto` подходит, если конкретный обработчик известен в этом месте.
Шаблонный параметр подходит алгоритму, который сразу вызывает переданное
поведение. `std::function` удобен для поля класса, сменяемого обработчика
и контейнера обработчиков разных типов. Обычный указатель на функцию
достаточен для свободных функций без захваченного состояния.

## Есть ли в C++ делегаты

В C++ нет отдельного ключевого слова `delegate` и стандартного типа
`std::delegate`. Термин встречается в библиотеках и фреймворках: точный смысл
и правила владения зависят от конкретной библиотеки.

Для аналога делегата с одним обработчиком можно взять
`std::function<void(int)>`, связать метод с объектом лямбдой или `std::bind`
и вызвать обработчик при событии. Так устроен класс `Button` в
[examples.cpp](examples.cpp): `set_handler()` заменяет обработчик,
`click()` проверяет его и вызывает, `set_handler(nullptr)` снимает подписку.
Псевдоним `using Handler = std::function<void(int)>` даёт имя типу,
но не создаёт новую возможность языка.

Несколько подписчиков требуют отдельного механизма: например, списка
обработчиков и правил подписки/отписки. Это естественное продолжение к
[паттерну Observer](../../patterns/observer.cpp). `std::function` сама
не рассылает событие нескольким получателям.

Делегирующий конструктор из C++11 — другая тема: один конструктор класса
вызывает другой конструктор того же класса.

## Время жизни: главная проверка перед сохранением callback

Если обработчик будут вызывать позже, все объекты, к которым он обращается,
должны ещё существовать. Опасный пример (не запускать):

```cpp
std::function<int()> broken() {
    int value = 42;
    return [&value]() { return value; }; // После возврата ссылка повиснет.
}
```

Для независимого снимка данных захвати `[value]`. Для обращения к внешнему
объекту заранее определи, кто владеет им и когда снимается подписка.
Захват `[this]` сохраняет указатель, а не копию объекта, и тоже не продлевает
его жизнь. В примере `Button` обработчик снимается, пока `Counter` ещё жив.

При необходимости совместного владения можно захватить `std::shared_ptr`
по значению. Если объект сам хранит обработчик с `shared_ptr` на себя,
возникает цикл владения; для такого случая изучи `std::weak_ptr` и `lock()`.
Это дополнительная тема после основ умных указателей.

## Что изучить дальше

1. Переписать каждую привязку из примеров лямбдой и объяснить захваты.
2. Выполнить мини-проект из [практики](practice.md): очередь команд.
3. В C++17 сравнить `(object.*method)(value)` с
   `std::invoke(method, object, value)`.
4. В C++20 сравнить `std::bind(subtract, 10, _1)` с
   `std::bind_front(subtract, 10)`; placeholders для `bind_front` не нужны.
5. После move semantics изучить `std::move_only_function` из C++23:
   она может хранить лямбду с перемещённым `std::unique_ptr`.
   В отличие от `std::function`, вызывать её пустой нельзя:
   исключение `std::bad_function_call` для этого случая не гарантируется.

## Сборка и запуск

Из корня проекта:

```bash
cmake -S . -B build
cmake --build build --target cpp11_functional_examples
./build/c++11/functional/cpp11_functional_examples
```

Или напрямую, независимо от настроек основной программы:

```bash
c++ -std=c++11 -Wall -Wextra -Wpedantic -Wshadow -Wconversion c++11/functional/examples.cpp -o /tmp/cpp11_functional_examples
/tmp/cpp11_functional_examples
```

Ранний [пример std/function.cpp](../../std/function.cpp) оставлен для сравнения:
там дополнительно есть указатель на поле класса и рекурсивная лямбда.

## Источники для сверки

- [Проект N3337, раздел Function objects](https://timsong-cpp.github.io/cppwp/n3337/function.objects):
  объявления и требования к `function`, `bind` и `reference_wrapper` эпохи C++11.
- [Проект N4659, std::invoke](https://timsong-cpp.github.io/cppwp/n4659/func.invoke): C++17.
- [P0356R5, Bind front](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2018/p0356r5.html):
  предложение для `bind_front`; это документ предложения, а не окончательный стандарт.
- [Проект C++23 N4950](https://www.open-std.org/jtc1/sc22/wg21/docs/papers/2023/n4950.pdf):
  разделы `func.bind.partial` и `func.wrap.move`.
