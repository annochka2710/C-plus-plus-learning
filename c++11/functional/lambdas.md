# Лямбды в C++11

Лямбда — выражение, создающее объект с `operator()`. Такой объект удобно
передать алгоритму или сохранить как обработчик. Лямбды появились в C++11.
Эта заметка дополняет [модуль std::function и std::bind](notes.md).

## Синтаксис

```cpp
auto square = [](int value) -> int { return value * value; };
int result = square(4); // 16
```

| Часть | Назначение |
|---|---|
| `[]` | Захваты: какие локальные переменные доступны внутри |
| `(int value)` | Параметры будущего вызова |
| `-> int` | Тип результата; для простого `return` можно опустить |
| `{ return value * value; }` | Тело функции |

Каждое отдельное лямбда-выражение имеет собственный безымянный тип.
`auto` сохраняет этот тип, а `std::function<int(int)>` позволяет скрыть его
за сигнатурой и впоследствии заменить обработчик другим совместимым объектом.

## Захват по значению и по ссылке

```cpp
int offset = 10;
auto snapshot = [offset](int value) { return value + offset; };
auto live = [&offset](int value) { return value + offset; };
offset = 20;
// snapshot(1) == 11: копия сделана при создании лямбды.
// live(1) == 21: читается исходная переменная при вызове.
```

Захваты сохраняются при **создании** объекта лямбды. Параметры передаются
при каждом **вызове**. Захват по значению — не обязательно глубокая копия:
копия указателя всё ещё ведёт к тому же объекту.

| Захват | Значение |
|---|---|
| `[]` | Без захваченных локальных переменных |
| `[x]` | Своя копия `x` |
| `[&x]` | Обращение к исходному `x` |
| `[x, &y]` | Копия `x` и ссылка на `y` |
| `[=]` | Неявный захват используемых локальных переменных по значению |
| `[&]` | Неявный захват используемых локальных переменных по ссылке |
| `[this]` | Указатель на текущий объект; доступ к его полям и методам |

Для отложенных обработчиков предлагаю явные захваты: так легче проверить
время жизни каждого объекта. Глобальные и статические переменные можно
использовать без захвата. `[=]` при обращении к полям класса в C++11 может
неявно захватить `this`: это не копия всего объекта.

## mutable: изменяем свою копию

```cpp
int count = 0;
auto next = [count]() mutable { return ++count; };
auto independent = next;
// next() == 1, следующий next() == 2.
// independent() == 1; исходный count по-прежнему равен 0.
```

По умолчанию `operator()` лямбды константный. `mutable` делает его
неконстантным и разрешает менять захваченные обычные копии.
Это не меняет исходную переменную и не снимает её собственный `const`.
Для изменения объекта через захваченную ссылку `mutable` не требуется:

```cpp
auto increment = [&count]() { ++count; };
increment(); // Исходный count становится 1.
```

Сравни с [mutable для полей класса](../../c++98/mutable/notes.md):
там ключевое слово разрешает менять отдельное поле в `const`-методе,
а здесь меняет константность оператора вызова лямбды.

## Лямбда как параметр алгоритма

```cpp
std::vector<int> values{3, 1, 4, 2};
std::sort(values.begin(), values.end(),
          [](int left, int right) { return left > right; });
// 4, 3, 2, 1
```

Для этого нужны `<vector>` и `<algorithm>`. Сортировка вызывает лямбду,
чтобы узнать, должен ли левый элемент идти раньше правого.
Не используй `>=`: компаратор должен задавать строгий порядок,
в частности сравнение элемента с самим собой возвращает `false`.
Алгоритмы могут копировать функторы: не рассчитывай получить итоговый
счётчик вызовов из внутренней копии лямбды после работы алгоритма.

## Время жизни и преобразование к указателю

Лямбду можно вернуть из функции через `std::function` в C++11,
но нельзя оставлять в ней ссылки на завершившиеся локальные объекты.
Безопасный снимок:

```cpp
std::function<int()> make_answer() {
    int value = 42;
    return [value]() { return value; };
}
```

`[&value]` здесь оставил бы висячую ссылку. `[this]` тоже не продлевает
жизнь объекта: перед его разрушением нужна отписка либо другая схема владения.

Лямбда **без захватов** может преобразовываться к указателю на функцию:

```cpp
int (*increment)(int) = [](int x) { return x + 1; };
```

Лямбда с захватами так не преобразуется: обычному указателю на функцию
негде хранить индивидуальное состояние объекта лямбды.

## Границы стандартов

| Стандарт | Дополнение |
|---|---|
| C++11 | Лямбды, захваты, `mutable`, явный тип результата |
| C++14 | Обобщённые параметры `[](auto x)`, захват с инициализатором `[x = expression]` |
| C++17 | Захват `[*this]`: копия текущего объекта |
| C++20 | Явный список параметров шаблона `[]<typename T>(T x)` |

Все [запускаемые примеры этой темы](lambda_examples.cpp) используют C++11.
Базовые правила можно сверить с
[проектом N3337, Lambda expressions](https://timsong-cpp.github.io/cppwp/n3337/expr.prim.lambda).

## Практика

1. До запуска предскажи вывод `lambda_examples.cpp` и объясни захваты.
2. Напиши `std::count_if`, считающий числа больше захваченного порога.
   Для `{3, 1, 4, 2}` и порога 2 результат должен быть 2.
3. Замени `[offset]` на `[&offset]`: объясни изменение результата после
   присваивания `offset = 20` и требование к времени жизни.
4. Сделай счётчик с `mutable`, скопируй до первого вызова и проверь
   независимость состояния. Затем сделай два обработчика с общей ссылкой.
5. Напиши фабрику обработчика прибавления фиксированного числа:
   `std::function<int(int)> make_adder(int delta)`.
   Возвращённый обработчик должен работать после завершения фабрики.
6. Перейди к [событиям с подпиской и отпиской](events.md).

Сборка из корня:

```bash
cmake -S . -B build
cmake --build build --target cpp11_lambda_examples
./build/c++11/functional/cpp11_lambda_examples
```
