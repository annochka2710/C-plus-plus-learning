# Просмотр и завершение процессов

Процесс — выполняющийся экземпляр программы со своими ресурсами:
адресным пространством, открытыми файлами и состоянием выполнения.
Одна программа может быть запущена в нескольких процессах.

Команды ниже предназначены для Bash в Linux. Для `ps`, `top`, `pgrep`
используются возможности пакета procps-ng.

## PID, PPID и задания оболочки

- **PID** — идентификатор процесса. После завершения номер может использоваться снова.
- **PPID** — PID родительского процесса.
- **PGID** — идентификатор группы процессов, например команд одного конвейера.
- **Задание Bash** — команда или конвейер, которыми управляет текущая оболочка.
  Номер задания `%1` и PID — разные вещи.

`$$` в обычной оболочке содержит её PID, а `$!` — PID последней команды,
запущенной в фоне. `wait` позволяет оболочке дождаться своего дочернего процесса
и получить его статус завершения.

## Просмотр списка: ps

`ps` показывает снимок состояния, а не постоянно обновляющийся список:

```bash
ps
ps -ef
ps aux
ps -u "$(id -un)" -o pid,ppid,stat,pcpu,pmem,etime,comm
ps -eo pid,ppid,stat,comm --forest
```

`ps` без опций показывает процессы текущего пользователя, связанные
с тем же терминалом. `-e` выбирает все процессы, `-f` включает полный формат.
`ps aux` — распространённая запись с BSD-опциями **без дефиса**;
не заменяй её на `ps -aux`.

`-u` выбирает пользователя, `-p` — конкретные PID, `-o` задаёт столбцы.
`--forest` показывает отношения родителей и потомков деревом.

| Поле | Значение |
|---|---|
| `PID`, `PPID` | Процесс и его родитель |
| `STAT` | Состояние и дополнительные признаки |
| `%CPU`, `%MEM` | Использование процессора и доля физической памяти |
| `ELAPSED` (`etime`) | Время с запуска |
| `TIME` | Накопленное процессорное время, а не время с запуска |
| `COMMAND` (`comm`) | Имя команды |
| `COMMAND` (`args`) | Командная строка с аргументами |

У `ps` процент CPU обычно усреднён за жизнь процесса. В `top`
измерение привязано к обновлениям, поэтому цифры могут отличаться.
Имена столбцов и некоторые детали зависят от выбранного формата.

## Поиск: pgrep

```bash
pgrep -a -x bash
pgrep -a -P "$$" -x sleep
```

`pgrep` ищет процессы; `-a` показывает PID и командную строку,
`-x` требует полного совпадения имени, `-P` ограничивает поиск потомками
непосредственно указанного родителя.

По умолчанию шаблон — регулярное выражение для имени процесса.
`-f` переключает поиск на всю командную строку: совпадений может стать больше.
Если совпадений нет, `pgrep` возвращает код `1`; это обычный результат поиска.

`pgrep` удобнее, чем `ps | grep`: второй вариант может включить в результат
сам процесс `grep`. Для завершения учебного процесса ниже сохраняем его PID
сразу после запуска, а не ищем все процессы с похожим именем.

## Наблюдение: top

```bash
top
```

Основные клавиши procps-ng `top`:

| Клавиша | Действие |
|---|---|
| `q` | Выйти из `top`, оставив наблюдаемые процессы работать |
| `P` | Сортировать по использованию CPU |
| `M` | Сортировать по использованию памяти |
| `c` | Переключить отображение командной строки |
| `h` | Показать справку |

Наблюдать один PID можно так:

```bash
top -p "$$"
```

Для скрипта подходит однократный пакетный вывод без интерактивного интерфейса:

```bash
top -b -n 1 -p "$$"
```

## Состояния процесса

Первый символ `STAT` в `ps` показывает основное состояние:

| Код | Что означает |
|---|---|
| `R` | Выполняется или готов выполняться |
| `S` | Прерываемое ожидание события, например у `sleep` |
| `D` | Непрерываемое ожидание, часто связанное с вводом-выводом |
| `T` | Приостановлен сигналом управления заданиями |
| `Z` | Уже завершился, но родитель ещё не забрал статус: zombie |

Дополнительные символы описывают другие признаки. Например,
`S+` — ожидающий процесс в группе переднего плана терминала.

Приостановленный процесс существует, но не выполняет обычный код.
Zombie уже закончил выполнение: повторный `kill` его не «уберёт»,
родитель должен забрать статус через семейство `wait`.

## Снятие процесса: kill отправляет сигнал

Снятие обычно означает завершение процесса. Команда `kill` отправляет
сигнал; его действие зависит от сигнала и обработчиков программы.
Успешный возврат `kill` ещё не означает, что процесс уже завершился.

| Сигнал | Назначение |
|---|---|
| `TERM` (`SIGTERM`) | Запросить завершение; программа может обработать или игнорировать |
| `INT` (`SIGINT`) | Запросить прерывание; обычно отправляется через `Ctrl+C` |
| `KILL` (`SIGKILL`) | Принудительное завершение без пользовательского обработчика |
| `STOP` (`SIGSTOP`) | Безусловно приостановить выполнение |
| `CONT` (`SIGCONT`) | Продолжить приостановленный процесс |
| `TSTP` (`SIGTSTP`) | Приостановка из терминала, обычно через `Ctrl+Z`; может обрабатываться |

Без указания сигнала `kill` отправляет `TERM`. `KILL` и `STOP` нельзя
перехватить, заблокировать или игнорировать. `KILL` не даёт программе
выполнить свою процедуру завершения и сохранить данные.

Обычная последовательность: проверить PID и команду, отправить `TERM`,
дать время на завершение и проверить результат. Если процесс остался
и принудительное завершение допустимо, использовать `KILL`.
Для состояния `D` даже `KILL` может не завершить процесс немедленно.

## Практика в одной оболочке: запускаем свой процесс

Выполняй следующие блоки по порядку в одном окне Bash:

```bash
sleep 300 &
demo_pid=$!
printf 'Учебный PID: %s\n' "$demo_pid"
ps -p "$demo_pid" -o pid,ppid,stat,etime,args
jobs -l
```

`&` запускает команду в фоне, оболочка продолжает принимать команды.
`sleep 300` ожидает 300 секунд и почти не расходует CPU.
Все сигналы ниже отправляем только этому PID.

### Приостановка и продолжение

```bash
kill -STOP -- "$demo_pid"
ps -p "$demo_pid" -o pid,ppid,stat,args
kill -CONT -- "$demo_pid"
```

После `STOP` ожидаем `T`. Доставка сигнала не синхронна с командой `ps`:
если состояние ещё не изменилось, повтори просмотр. После `CONT`
процесс снова выполняется или ожидает; для `sleep` обычно увидишь `S`.

### Проверка существования и завершение через TERM

```bash
kill -0 -- "$demo_pid"
ps -p "$demo_pid" -o pid,ppid,stat,args
kill -TERM -- "$demo_pid"
if wait "$demo_pid"; then
    printf 'Процесс вернул код 0\n'
else
    status=$?
    printf 'Статус wait: %s\n' "$status"
fi
unset demo_pid
```

`kill -0` не отправляет сигнал: проверяет существование PID и право
отправки сигнала. Это не проверка работоспособности программы и не гарантия,
что тот же процесс будет существовать позже. Ошибка может означать
отсутствие процесса или недостаток прав.

В Bash завершение сигналом даёт статус `128 + номер сигнала`.
Для обычного `sleep` после `TERM` в Linux ожидаем `143` (`128 + 15`).
Ненулевой статус здесь ожидаем: именно поэтому `wait` помещён в условие.
`wait` работает с дочерними процессами текущей оболочки; ждать произвольный
PID чужого процесса таким способом нельзя.

### Отдельный пример принудительного завершения

```bash
sleep 300 &
demo_pid=$!
ps -p "$demo_pid" -o pid,ppid,stat,args
kill -KILL -- "$demo_pid"
if wait "$demo_pid"; then
    printf 'Процесс вернул код 0\n'
else
    status=$?
    printf 'Статус wait: %s\n' "$status"
fi
unset demo_pid
```

Ожидаемый статус — `137` (`128 + 9`). Здесь `KILL` нужен для демонстрации;
обычный `sleep` завершился бы и через `TERM`.
Запись `kill -9` равнозначна отправке `KILL` в Linux; имя понятнее числа.

## Передний план, фон и Ctrl+C

В интерактивном Bash попробуй отдельно:

```bash
sleep 300
```

`Ctrl+C` обычно отправляет `INT` группе переднего плана, а не всем процессам
терминала. `Ctrl+Z` приостанавливает задание. После него `jobs -l` показывает
задание, `bg %1` продолжает задание номер 1 в фоне, `fg %1` возвращает
его на передний план. Сначала сверяй номер через `jobs`.
Для фонового задания `kill %1` отправляет `TERM` средствами Bash.

Задание может состоять из нескольких процессов конвейера. Завершение
одного родителя само по себе не гарантирует завершения всех его потомков.

## Другие команды и типичные ситуации

`pkill` посылает сигнал всем процессам, совпавшим с условиями поиска,
а Linux-команда `killall` выбирает процессы по имени. Совпадений может
быть несколько. Перед массовым действием проверяй список через `pgrep`;
для этих упражнений используй сохранённый PID.

`Permission denied` / `Operation not permitted` означает недостаток прав,
а `No such process` — отсутствие цели в момент проверки.
Для сигналов своим учебным процессам `sudo` не нужен.
Не подставляй `0` или отрицательные PID в эти примеры: они имеют
особое значение и могут адресовать сразу группы процессов.

Если сервис сразу появляется с новым PID, его может перезапускать
менеджер служб. Такую службу останавливают через её менеджер,
например `systemctl stop имя.service`, после проверки имени и назначения.

## Самостоятельные упражнения

1. Запусти два `sleep 300` в фоне и сохрани оба PID в разные переменные.
   Покажи только их через `ps -p "PID1,PID2"`, подставив сохранённые значения.
2. Найди прямых дочерних `sleep` своей оболочки через `pgrep`.
   Объясни назначение `-P`, `-x` и `-a`.
3. Приостанови один процесс через `STOP` и сравни его `STAT` со вторым.
   Продолжи его через `CONT`.
4. Заверши оба через `TERM`, вызови `wait` для каждого и объясни статусы.
5. Запусти отдельный `sleep`, открой для его PID `top` и выйди клавишей `q`.
   Убедись, что процесс остался, затем заверши его и вызови `wait`.
6. Объясни разницу между `TERM`, `KILL`, `STOP` и `Ctrl+Z`.
   Почему `kill -0` не доказывает, что приложение отвечает на запросы?

После упражнений заверши все созданные тобой процессы и получи их статусы
через `wait` в той же оболочке.

## Запуск готовых примеров

Из корня проекта:

```bash
bash linux/processes/examples.sh
```

Скрипт показывает только себя и свои учебные процессы, использует `top`
в пакетном режиме, демонстрирует `STOP`, `CONT`, `TERM`, `KILL` и `wait`.
Он не требует ввода или `sudo`; при выходе завершает оставшийся учебный процесс.

Связанный пример на C: [volatile и флаг обработчика SIGINT](../../c89-90/volatile/notes.md).
