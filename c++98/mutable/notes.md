# Ключевое слово mutable в C++98

`mutable` разрешает изменять отдельное нестатическое поле класса,
даже когда объект доступен как `const` или изначально объявлен константным.
Остальные поля продолжают подчиняться правилам `const`.

Ключевое слово существовало уже в C++98. В этом модуле рассматриваем
поля классов; применение `mutable` к лямбдам появилось в C++11.

## Зачем это нужно: const-метод с внутренним счётчиком

```cpp
class Value {
public:
    explicit Value(int value) : value_(value), reads_(0) {}

    int get() const {
        ++reads_;
        return value_;
    }

private:
    int value_;
    mutable unsigned int reads_;
};
```

`const` после списка параметров `get()` относится к объекту, на котором
вызывается метод. Через такой метод нельзя напрямую менять обычное поле
`value_`. Поле `reads_` помечено `mutable`, поэтому его менять разрешено.

```cpp
const Value value(42);
int result = value.get(); // result == 42, внутренний счётчик увеличился.
```

Если убрать `mutable`, выражение `++reads_` в `get() const` не скомпилируется.
Квалификатор метода не меняет тип возвращаемого значения: здесь возвращается
обычная копия `int`.

## Логическая константность

Иногда операция чтения меняет внутренние служебные данные:
заполняет кеш или ведёт диагностический счётчик. При этом смысловое
состояние объекта, которое представляет его основной интерфейс, остаётся прежним.

Например, получение числа слов не меняет текст. Сохранять уже вычисленное
число в кеше можно с помощью `mutable`, оставив метод чтения константным.
Это называют **логической константностью**.

Это проектное решение: компилятор разрешит менять любое поле с `mutable`,
но не проверит, насколько оно действительно служебное.
Если метод меняет сам текст или другое основное состояние объекта,
обычно правильнее сделать метод неконстантным.

## Практический пример: кеш числа слов

[examples.cpp](examples.cpp) содержит класс `TextStatistics`.
Словом считаем последовательность непробельных символов.
Первый запрос проходит по тексту, последующие используют готовый результат.

| Поле | Назначение | mutable |
|---|---|---|
| `text_` | Исходный текст | Нет |
| `cache_valid_` | Можно ли использовать кеш | Да |
| `cached_words_` | Сохранённое число слов | Да |
| `calculations_` | Число фактических пересчётов для наблюдения | Да |

Метод `word_count() const` заполняет кеш, только если `cache_valid_ == false`.
Метод `set_text()` меняет текст и сбрасывает признак актуальности кеша.
Если забыть сброс, очередной запрос вернёт результат для прежнего текста.

Счётчик нужен, чтобы увидеть разницу между повторным вызовом метода
и повторным вычислением. Получение самого счётчика не запускает пересчёт.
Передача `unsigned char` в `std::isspace` обеспечивает корректный аргумент
этой библиотечной функции и при отрицательных значениях обычного `char`.

## Const-ссылка и изначально const-объект

В примере есть оба случая:

```cpp
TextStatistics statistics("one two");
const TextStatistics& view = statistics;
```

Через `view` доступны константные методы. Изменение текста выполняется
через исходный неконстантный объект `statistics`. Это тот же объект,
поэтому `view` затем видит обновлённый текст и пересчитанный результат.

```cpp
const TextStatistics fixed("alpha beta");
```

Здесь сам объект создан как `const`. Его `mutable`-поля по-прежнему
можно изменять в `word_count() const`, а обычное поле `text_` — нельзя.

`mutable` не делает неконстантный метод доступным для `const`-объекта:
`fixed.set_text(...)` и `view.set_text(...)` не скомпилируются.
Он также не отменяет `private`: внешний код не получает доступ к кешу.

## Где можно писать mutable

| Объявление | Допустимо в C++98 |
|---|---|
| `mutable int cache;` как поле класса | Да |
| `mutable const int cache;` | Нет: само поле объявлено `const` |
| `mutable int& reference;` | Нет: поле является ссылкой |
| `static mutable int shared;` | Нет: поле статическое |
| `mutable int local;` внутри функции | Нет: это локальная переменная |

`mutable` ставится в объявлении поля, а `const` константного метода —
после списка его параметров. Инициализация полей в примерах выполняется
через список инициализации конструктора: инициализаторов прямо в объявлении
поля ещё не было в C++98.

## Mutable, const_cast и volatile

`mutable` явно обозначает изменяемые служебные поля в интерфейсе класса.
Для изменения их через константный объект не требуется `const_cast`.
Изменение обычного поля реально константного объекта после снятия
`const` через приведение приводит к неопределённому поведению.

`volatile` решает другую задачу — задаёт требования к обращениям к объекту.
Он не разрешает менять обычные поля через `const`-метод.
Ни `mutable`, ни `volatile` не обеспечивают синхронизацию потоков.
В частности, одновременное заполнение этого кеша несколькими потоками
требует отдельной синхронизации. Стандартных потоков в C++98 нет.

## Сборка и запуск

Из корня проекта:

```bash
mkdir -p build
c++ -std=c++98 -pedantic-errors -Wall -Wextra -Wshadow -Wconversion -O2 \
    c++98/mutable/examples.cpp -o build/mutable_examples
./build/mutable_examples
```

Ожидаемый вывод:

```text
Через const-ссылку:
Первый запрос: слов=2, вычислений=1
Повторный запрос: слов=2, вычислений=1
После изменения текста: слов=3, вычислений=2
Пустой текст: слов=0, вычислений=3
Изначально const-объект:
Первый запрос: слов=2, вычислений=1
Повторный запрос: слов=2, вычислений=1
```

Во втором запросе счётчик не увеличился. После изменения текста результат
пересчитан. Пустой текст тоже кешируется: ноль является корректным
результатом, поэтому для признака актуальности используется отдельный `bool`.

Пример также подключён к общей сборке:

```bash
cmake -S . -B build
cmake --build build --target cpp98_mutable_examples
./build/c++98/mutable/cpp98_mutable_examples
```

## Практика

1. Убери `mutable` у `cache_valid_`, затем отдельно у `cached_words_`.
   Попробуй собрать и объясни ошибки. После эксперимента восстанови объявления.
2. Раскомментируй один из запрещённых вызовов `set_text` в `main`.
   Почему `mutable` не разрешает этот вызов?
3. Добавь третий запрос без изменения текста. Сколько должно быть пересчётов?
4. Закомментируй сброс `cache_valid_` в `set_text()` и проверь результат.
   Почему программа компилируется, но работает неправильно? Восстанови сброс.
5. Проверь строки из одних пробелов, табуляцию, переводы строк и одно слово.
   Для повторного запроса каждой строки проверь отсутствие лишнего пересчёта.
6. Объясни назначение каждого `mutable`-поля. Какие изменения основного
   состояния потребуют сброса кеша, если класс станет сложнее?
