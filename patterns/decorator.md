# Декоратор (Decorator)

Декоратор — структурный паттерн: обёртка добавляет поведение объекту,
сохраняя его интерфейс. Обёртки можно вкладывать друг в друга.

[Пример на C++](decorator.cpp) адаптирован из
[статьи Википедии, раздел C++](https://ru.wikipedia.org/wiki/Декоратор_(шаблон_проектирования)#C++).
Добавлены `override`, `explicit` и перемещение указателей в поля.

## Участники примера

| Класс / функция | Роль |
|---|---|
| `IComponent` | Общий интерфейс с методом `operation()` |
| `Component` | Базовое поведение: печатает `World!` и перевод строки |
| `DecoratorOne` | Печатает `, ` перед вызовом вложенного объекта |
| `DecoratorTwo` | Печатает `Hello` перед вызовом вложенного объекта |
| `Operation` | Клиент: вызывает метод через `IComponent&` |

## Порядок вызовов

В `main()` создаётся цепочка:

```text
Operation(greeting)
  → DecoratorTwo::operation()  печатает "Hello"
    → DecoratorOne::operation()  печатает ", "
      → Component::operation()  печатает "World!\n"
```

Вызов виртуального метода выбирает реализацию фактического объекта.
Порядок обёрток влияет на результат; дополнительное действие можно
выполнить и после вызова `component_->operation()`.

## Почему это декоратор

Обёртки наследуют **интерфейс** `IComponent` и **содержат** другой `IComponent`.
Поэтому клиент одинаково использует исходный компонент и цепочку обёрток.
Комбинации поведения собираются при создании объектов, без отдельного
подкласса `Component` для каждой комбинации. Цена — дополнительные объекты
и необходимость учитывать порядок обёрток.

`shared_ptr` управляет временем жизни вложенных объектов. Виртуальный
деструктор позволяет корректное удаление через базовый указатель.
Конструкторы ожидают непустые указатели. При единственном владельце
цепочки можно использовать `unique_ptr`.

## Сборка и запуск

Из корня репозитория, нужен C++11 или новее:

```bash
g++ -std=c++11 -Wall -Wextra -Wpedantic patterns/decorator.cpp -o /tmp/decorator
/tmp/decorator
```

Результат:

```text
Hello, World!
```
