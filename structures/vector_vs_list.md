# std::vector и std::list

Это стандартные контейнеры C++. Примеры находятся в `vector.cpp` и `list.cpp`.
Существующая реализация в `linked_list.hpp` — отдельный учебный материал.

## Как хранятся элементы

`std::vector` — динамический массив. Элементы хранятся последовательно
в одном блоке памяти. Можно сразу обратиться к элементу по индексу.

```text
индекс:   0    1    2    3
данные: [10] [20] [30] [40]
```

`std::list` — двусвязный список. Элементы располагаются в узлах,
связанных в обоих направлениях. Узлы не обязаны находиться рядом в памяти.
Чтобы добраться до элемента в середине, нужно пройти по связям.

```text
[10] <-> [20] <-> [30] <-> [40]
```

## Сложность операций

`n` — число элементов. Сложность описывает рост количества операций,
а не конкретное время в миллисекундах.

- `O(1)` — число операций не зависит от размера контейнера.
- `O(log n)` — число операций растёт логарифмически.
- `O(n)` — в худшем случае требуется число операций, пропорциональное `n`.

Таблица относится к отдельным элементам простого типа, например `int`.
Для сложных объектов стоимость копирования, перемещения и уничтожения тоже влияет на время.

| Операция | std::vector | std::list |
|---|---|---|
| Доступ к элементу по индексу | `O(1)` | `O(n)`, нужен проход; `operator[]` отсутствует |
| Поиск значения через `std::find` | `O(n)` | `O(n)` |
| Добавление в конец | Амортизированное `O(1)`, отдельное перевыделение — `O(n)` | `O(1)` |
| Добавление в начало | `O(n)` | `O(1)` |
| Вставка одного элемента в середину при известной позиции | `O(n)` | `O(1)` |
| Поиск значения и вставка перед ним | `O(n)` | `O(n)` |
| Удаление одного элемента из середины при известной позиции | `O(n)` | `O(1)` |
| Удаление последнего элемента | `O(1)` | `O(1)` |

## Почему вставка в list не всегда быстрее

Если итератор на нужный узел уже есть, `list.insert(position, value)`
вставляет новый узел за `O(1)`. Перемещать остальные элементы не требуется.

Но если нужно сначала найти число 30, получится:

```cpp
auto position = std::find(values.begin(), values.end(), 30); // O(n)
if (position != values.end()) {
    values.insert(position, 25); // O(1) для list
}
```

Итоговая сложность для списка — `O(n)`.
Поиск позиции по номеру через `std::next` тоже требует прохода.

У `vector` позицию по индексу можно получить за `O(1)`,
но вставка в середину сдвигает последующие элементы. Даже при достаточной
свободной ёмкости сдвиг остаётся, поэтому худший случай — `O(n)`.

## Поиск в отсортированных данных

Для `vector` можно использовать `std::lower_bound` за `O(log n)`.
Он возвращает первый элемент, не меньший искомого, либо `end()`.
Нужно отдельно проверить, что найденный элемент равен искомому.
Данные должны быть упорядочены для используемого сравнения.

`std::lower_bound` применим и к отсортированному `list`, но там
получится `O(log n)` сравнений и `O(n)` перемещений итератора.
Быстрого перехода к середине по индексу у списка нет.

Сортировка — отдельная операция. Если данные ещё не отсортированы,
её стоимость тоже нужно учитывать.

## size, capacity и reserve у vector

- `size()` — число существующих элементов.
- `capacity()` — сколько элементов помещается без перевыделения памяти.
- `reserve(8)` обеспечивает ёмкость минимум для 8 элементов, но не меняет размер.

Когда места хватает, `push_back` создаёт только новый элемент в конце.
Когда места не хватает, контейнер выделяет больший блок и переносит элементы.
Редкие дорогие расширения распределяются по серии добавлений —
это и означает амортизированное `O(1)`.

## Что происходит с итераторами

Итератор обозначает позицию в контейнере. Перед чтением результата поиска
нужно проверить, что он не равен `end()`: `end()` находится за последним элементом.

У `vector`:

- Перевыделение памяти делает все старые итераторы, указатели и ссылки
  на элементы недействительными, включая старый `end()`.
- Вставка без перевыделения делает недействительными итераторы и ссылки
  на элементы в позиции вставки и после неё, а также старый `end()`.
- Удаление делает недействительными итераторы и ссылки на удалённый элемент
  и на элементы после него, а также старый `end()`.

У `list`:

- Вставка сохраняет итераторы и ссылки на существующие элементы.
- Удаление делает недействительными только итераторы и ссылки на удалённые элементы.

## Практическая скорость и выбор

`vector` часто удобен для хранения последовательности, обхода и доступа по индексу.
Соседние элементы находятся рядом, что помогает процессорному кешу.
Поэтому даже при одинаковом `O(n)` последовательный поиск в `vector`
часто быстрее, чем в `list`.

`list` полезен, когда часто вставляют и удаляют элементы по уже сохранённым
итераторам, а остальные итераторы должны оставаться действительными.
Узлам нужны дополнительные связи; выделение памяти под узлы и переходы
между ними влияют на реальное время работы.

Оценки сложности не заменяют измерение на конкретной задаче.
Эти примеры показывают поведение контейнеров, а не измеряют скорость.

## Сборка и запуск

Выполнять из корня проекта в Linux. Каждый пример — отдельная программа
со своей функцией `main`, поэтому собираем их отдельно:

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic structures/vector.cpp -o /tmp/vector_example
/tmp/vector_example

g++ -std=c++20 -Wall -Wextra -Wpedantic structures/list.cpp -o /tmp/list_example
/tmp/list_example
```

2. Добавь в `vector` число, нарушающее сортировку. Объясни, почему перед
   `lower_bound` нужно снова упорядочить данные.
